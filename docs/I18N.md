# Streamlit internationalization

## Implementation status

Feature 009 is **in progress, not release-ready**. The language selector, navigation,
authentication, workspace controls, shared download captions, and interpretation-card
headings use centralized EN/VI resources. Page bodies, specialized evidence views,
charts, and the complete output vocabulary still need migration. Selecting VI currently
produces a partially translated application; do not claim complete EN/VI coverage.

## Resources

`config/language/en.json` and `config/language/vi.json` contain:

- `code`: uppercase locale ID; filename is the lowercase ID plus `.json`.
- `name`: the language's self-name in the selector.
- `translations`: a flat object of semantic dot-delimited keys and UTF-8 text.
- `output_mappings.columns`: exact raw header to translation-key mappings.
- `output_mappings.values`: raw **field name** to a dictionary of exact raw values
  and translation keys. Never use global find/replace on arbitrary text.

EN/VI must have identical translation keys, named interpolation placeholders, and
output mappings. Preserve units, uncertainty, historical/locked-test distinctions,
scientific caveats, and numerical formatting when translating a phrase.

## Static text

```python
from components.language import get_translator

i18n = get_translator(st)
st.caption(i18n.text("app.active_evidence", name=root.name))
```

Keep entire sentences and named placeholders in resources, not concatenated language
fragments in page code. No language-specific `if` branches are needed in renderers.
Use stable raw IDs for widget values/keys and translate only display labels using
`format_func`. The session's `app_language` is validated before selector construction.
No session language is stored in a global variable or shared resource cache.

## Evidence display

```python
st.dataframe(i18n.frame(raw_frame))
st.json(i18n.record(raw_metadata))
label = i18n.column("status")
value = i18n.value(raw_status, field="status")
```

These are presentation projections. Use `raw_frame`, not the localized frame, for
filtering, calculations, inference, chart coordinates, and raw downloads. Unknown
values, non-string values, and values in unmapped fields pass through unchanged.
`record()` is deliberately shallow: explicitly project known metadata at each render
boundary rather than recursively translating arbitrary user content. Header collisions
retain raw headers instead of losing columns/metadata entries. Existing artifacts and
producer schemas do not change and must not be regenerated just for translation.

## Validation and fallback

Run `.venv/bin/pytest -q tests/test_i18n.py tests/test_i18n_ui.py`.
`load_catalog()` defaults to strict validation and reports malformed resources, missing
keys, placeholder mismatches, and invalid mapping targets. Runtime loading logs invalid
secondary resources and uses English. A malformed default EN resource is a deployment
error. Missing keys or interpolation arguments log their key (not user values) and
render `common.unavailable`, never raw placeholders. Resources are reloaded when file
mtime/size changes; locale catalogs are cached, but user language selection is not.

## Add another language

1. Copy `en.json` to `<code>.json` in `config/language/`.
2. Set `code` and the native `name`; translate every value under `translations`.
3. Retain exactly the same keys, interpolation parameters, and output mappings.
4. Validate with `load_catalog()` and update the expected supported-locale test.
5. Add AppTests for the new locale. Discovery is automatic; do not edit page modules.

## Known verification limits

AppTest covers logic and rendered element text, not actual browser layout or screenshots.
Browser verification and complete page/string coverage remain acceptance gates.
