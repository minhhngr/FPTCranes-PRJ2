# Branch A Segmentation v3 — placement and integration guide

This revision implements three changes:

1. **Subsample stability** in addition to optimizer-seed stability.
2. **Explicit PCA clustering space** selected by cumulative DEV variance; PC1/PC2 are visualization-only.
3. **Evidence-only Streamlit**: tokenization, profile derivation, aggregation, family-balance diagnostics and candidate joins are generated by the offline pipeline.

## Files to add

### `src/ai_job_market/segmentation_stability.py`
Offline statistical stability module.

Responsibilities:
- draw repeated row subsamples without replacement;
- refit the same algorithm/K;
- compare the subsample partition with the full-DEV reference partition using ARI;
- return mean/std/p10/min ARI and per-resample evidence.

### `src/ai_job_market/segmentation_evidence.py`
Offline evidence builder.

Responsibilities:
- deduplicated posting-level skill token profiles;
- job-domain, experience, company, geography and market-signal profiles;
- country/city cluster profiles;
- candidate K coordinates and cluster-balance tables;
- run-specific narrative evidence for Streamlit.

### `tests/test_segmentation_v3.py`
Contract tests for the new Branch-A design.

## Files to replace/update

### `src/ai_job_market/core.py`
Replace the existing `FamilyBalancedEncoder` and `run_segmentation()` with the v3 versions supplied in this project.

Major changes:
- `FamilyBalancedEncoder.transform_family_blocks()` exposes actual fitted family blocks to the offline pipeline;
- PCA is fitted on DEV and keeps enough components to reach `pca_variance_threshold`;
- clustering uses PC1..PCN, not only PC1/PC2;
- PC1/PC2 remain a display projection;
- every KMeans/GMM candidate receives seed-stability + subsample-stability + minimum-share gates;
- all Branch-A evidence tables are generated before Streamlit starts.

The `run_pipeline()` Branch-A call also passes the new config and saves `segmentation_insights.json`.

### `config/project.yaml`
Replace the `segmentation:` block with the v3 block. The key settings are:

```yaml
segmentation:
  k_min: 2
  k_max: 8
  use_family_balancing: true

  pca_variance_threshold: 0.85
  pca_min_components: 2
  pca_max_components: null
  visualization_components: 2

  stability_seeds: [11, 23, 42, 71, 101]
  stability_min: 0.90

  resample_stability:
    enabled: true
    n_resamples: 12
    sample_fraction: 0.85
    min_mean_ari: 0.75
    random_seed: 2026

  min_cluster_share: 0.05
  silhouette_tolerance: 0.01
```

### `src/pages/page03_segmentation.py`
Replace the old Streamlit page completely.

The v3 page:
- does not import `normalize_skills`;
- contains no `.fit()`;
- contains no `.groupby()`;
- reads saved evidence tables only;
- shows actual family norm before/after balancing;
- shows full PCA explained-variance curve and clearly distinguishes cluster space vs 2D display space;
- shows both seed ARI and subsample ARI for K selection;
- reads `segmentation_insights.json` for chart commentary.

## Current reproduced result on the bundled dataset

With the v3 representation, the family-balanced encoded matrix has 199 dimensions. The DEV-fitted PCA needs **15 components** to retain about **85.3%** cumulative variance; PC1+PC2 retain only about **43.3%**, therefore PC1/PC2 are not used as the full clustering contract.

The current official solution is **KMeans, K=2**. It passes both stability gates in the reproduced run:
- seed stability ARI: **1.000**;
- mean 85%-subsample ARI: **0.971**;
- minimum cluster share: about **36.2%**;
- silhouette in the 15-PC clustering space: about **0.210**.

The lower silhouette than the former 2-PC workflow is expected: the v3 score evaluates separation in a much richer 15-PC space instead of a potentially over-simplified 2D projection. This is a more defensible representation of the actual clustering problem.
